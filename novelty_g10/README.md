# G10 — Controlled test-file version pilot (protocol before outcomes)

One lexicographically first eligible task per each of the three G9 Verified settings, chosen among the six frozen all-FTP-name final-patch-linked benchmark nonpasses. No substitutions for unavailable images or environment failures. Use the official instance image with base commit verified and image digest recorded. Five cells: base with local/base tests, base with reference tests, candidate with local final tests, candidate with reference tests, developer gold patch with reference tests. Same exact FTP node names and pytest invocation. Require identical non-test staged-tree digest in each base/candidate crossover. Strong witness: candidate-local PASS, candidate-reference FAIL, base-reference FAIL, gold-reference PASS; no collection errors, skips, timeouts, or missing JUnit reports. Full file versions differ only on official test paths. No original traces executed, no arbitrary commands from source; code runs offline inside nonprivileged disposable Docker containers, with no host credentials or sensitive mounts. Aggregate-only results. This is a controlled pilot for a test-version effect, not a full benchmark rerun, prevalence estimate, or proof of objective correctness. Test adequacy and test augmentation are established concepts (e.g., Li et al., STING, arXiv:2604.01518); G10 narrowly tests whether same-named local evidence transfers across test-file versions in the frozen historical examples. Main MR31R9-EP2 unchanged.
